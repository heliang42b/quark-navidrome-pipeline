# 案例：319 首歌从一个网盘索引站搬进 Navidrome

这是一个真实跑完的案例，记录数据、失败类型和踩过的坑，供参考。

## 背景与约束

目标是给自建 Navidrome（`localhost:4533`）补齐某位华语歌手的全部作品。

约束条件：

- 站点是**网盘索引站**，自己不存音频，每首歌只给一个夸克网盘分享链接，少数给百度云
- 没有 SVIP，夸克免费账号有**每日下载额度**和**单文件大小限制**
- 站点接口有限速，触发后会封禁，不能暴力拉
- 要求只保留**原唱**，翻唱、伴奏、Live、采访、饭制全部剔除

## 流程

```
搜索 100 页（2000 条记录）
        │  每页 2.7s，约 4~5 分钟，断点续抓
        ▼
归并去重 → 319 个歌名
        │  按歌名聚合，同一首歌可能有多条分享
        ▼
逐条取分享链接 → 每首挑最高音质的那条
        │
        ▼
夸克：转存 → 轮询任务 → 取直链 → 下载 → 打标签 → 删网盘文件
        │  单首走完约 8~15 秒；网盘里不长期留文件
        ▼
入库 259 首 / 5.22 GB
```

## 结果

标签全部校正为 `title` / `artist` / `album` / `album_artist`，226 首带同步歌词 `.lrc`。

## 缺口分析

319 个歌名里拿到 259 首，剩下的 60 首分成四类：

| 类型 | 数量 | 原因 | 处理 |
|---|---|---|---|
| 当日额度耗尽 | 11 | 报 `download file size limit` | 次日重跑 `rescue.py` |
| 只有百度云 | 19 | 站点只给了百度分享 | 需要百度账号，本项目不支持 |
| 整专辑压缩包 | 6 | 单文件超免费额度 | 需要 SVIP；但其中单曲多已单独下到 |
| 翻唱 / 噪音 / 错文件 | 24 | 站点收录了非原唱内容 | 主动剔除，不算缺口 |

## 失败类型与应对

跑的过程中遇到的错误基本可以归成五类，处理方式不一样：

1. **`download file size limit`**
   不是 bug，是免费账号的单文件上限。当日额度用完后整批都会失败，必须等第二天，重试无用。

2. **直链为空（404）**
   转存是异步任务，刚转存完立刻取直链经常拿不到。要等任务 `status=2`，再退避重试 6 次。

3. **分享失效**
   站点里的分享链接会过期或被取消，这类直接跳过并记录，不重试。

4. **多轨分享**
   有些「单曲」链接进去其实是整张专辑文件夹，需要递归遍历取音频，不能只取第一个文件。

5. **同名不同码率**
   早期抓到的 128k mp3 和后来的 FLAC 会撞名。入库时同名的低码率文件要主动删掉，否则 Navidrome 里会出现重复条目。

## 五个结论

**1. 站点限速是硬约束**
`/api/music/search` 60 秒内 30 次，超了封 180 秒。按每分钟 22 次跑刚好安全，调快一定被封。

**2. 网盘空间可以不留痕**
「转存 → 下载 → 删除」逐首处理，全程网盘占用接近零，不会被容量卡住。代价是每首多两次 API 调用。

**3. 标签决定 Navidrome 的观感**
`album_artist` 必须写歌手名。只写 `artist` 的话，合辑会被拆成一堆「未知艺术家」，整个库的专辑视图就废了。

**4. 清理比下载更费功夫**
319 个歌名里有 24 个是翻唱、伴奏、采访、饭制，光靠标题正则不够——「夜上海」「祝你生日快乐」这种标题完全合法，只能人工判断。`cleanup.py --dry` 先看再删是必要的。

**5. 断点续抓必须做**
抓 100 页要五分钟，中途断一次就得从头来。每页落盘成 `data/page_XXX.json`，重跑时跳过已存在的页。

## 复现

```bash
export MUSIC_DIR="/data/music/artist"
python harvest.py        # 抓取
python analyze.py        # 归并
python siteshares.py     # 取分享链接
python quark_qr.py       # 扫码登录
python quark_dl.py       # 下载入库
python rescue.py         # 次日重试失败项
python retag.py          # 补专辑名
python cleanup.py --dry  # 先看要删什么
python cleanup.py        # 真删
python verify_db.py      # 核对数量
```
